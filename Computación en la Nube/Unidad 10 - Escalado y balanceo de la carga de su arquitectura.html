1. ¿Qué es la alta disponibilidad?

La alta disponibilidad (High Availability o HA) es un concepto fundamental en cloud computing.

El objetivo es que una aplicación permanezca funcionando incluso cuando algo falla.

Problema real

Imagina una página web con un único servidor: 

Usuarios
↓
Servidor único

Si ese servidor falla:

  • La web deja de funcionar
  • Los usuarios no pueden entrar
  • La empresa pierde dinero

Objetivo de HA

Evitar que un único fallo destruya todo el sistema.

Cómo se consigue

  • Varios servidores
  • Balanceadores
  • Replicación
  • Auto Scaling
  • Redundancia
Las empresas modernas intentan que sus servicios estén disponibles prácticamente 24/7.
Pregunta típica: Alta disponibilidad NO significa “nunca falla”, sino minimizar caídas.

2. El problema del servidor único

Muchos principiantes imaginan aplicaciones funcionando en un solo servidor.

Ejemplo sencillo

1000 usuarios
↓
1 servidor EC2

Problemas

  • Puede saturarse
  • Puede quedarse sin RAM
  • Puede apagarse
  • Puede caerse la aplicación

Punto único de fallo

Si existe un solo servidor, ese servidor es crítico.

Cuando falla: 

Servidor caído
↓
Aplicación caída

Problema de rendimiento

Si demasiados usuarios llegan simultáneamente:

  • La web se vuelve lenta
  • Las peticiones tardan
  • Puede dejar de responder
Las arquitecturas modernas evitan depender de un único servidor.

3. ¿Qué es el balanceo de carga?

El balanceo de carga consiste en repartir tráfico entre varios servidores.

Sin balanceador

Usuarios
↓
1 EC2 saturada

Con balanceador

Usuarios
↓
Load Balancer
↙        ↘
EC2      EC2

Qué consigue

  • Repartir tráfico
  • Evitar saturación
  • Mejorar rendimiento
  • Mayor disponibilidad

Explicación sencilla

El balanceador funciona como un “repartidor”.

Cuando llegan usuarios:

  • Envía unos al servidor 1
  • Otros al servidor 2
  • Otros al servidor 3
El usuario normalmente ni siquiera sabe qué servidor está atendiendo su petición.

4. Elastic Load Balancing (ELB)

Elastic Load Balancing es el servicio AWS encargado del balanceo de carga.

Qué hace automáticamente

  • Distribuir tráfico
  • Detectar servidores caídos
  • Enviar tráfico solo a servidores sanos
  • Escalar automáticamente

Funcionamiento básico

Usuario entra web
↓
ELB recibe petición
↓
ELB decide servidor
↓
Servidor responde

Health Checks

ELB comprueba constantemente si los servidores siguen vivos.

Si un servidor falla: 

ELB deja de enviar tráfico
Pregunta típica: ELB mejora disponibilidad porque evita enviar tráfico a servidores rotos.

6. ¿Qué es Auto Scaling?

Auto Scaling permite crear o eliminar servidores automáticamente según demanda.

Problema sin Auto Scaling

Imagina una tienda online:

  • Pocos usuarios normalmente
  • Muchísimos usuarios en rebajas

Si solo tenemos un servidor: 

Muchos usuarios
↓
Servidor saturado

Con Auto Scaling

Muchos usuarios
↓
AWS crea nuevas EC2

Ventajas

  • Escalado automático
  • Menor coste
  • Alta disponibilidad
  • Mayor rendimiento
Auto Scaling es una de las herramientas más importantes en AWS.

7. Escalado ascendente y descendente

Escalado ascendente

Cuando aumenta tráfico: 

2 EC2
↓
5 EC2

AWS añade servidores automáticamente.

Escalado descendente

Cuando baja tráfico: 

5 EC2
↓
2 EC2

AWS elimina servidores sobrantes.

Objetivo

  • No quedarse corto
  • No pagar de más
El sistema busca equilibrio entre coste y rendimiento.

¿Qué ocurre en escalado descendente?

Se eliminan servidores sobrantes
Se crean más EC2
Se crean buckets
Se aumenta RAM local

8. Escalado vertical vs horizontal

Escalado vertical

Consiste en hacer MÁS potente un único servidor.

Ejemplo

2 GB RAM
↓
16 GB RAM

Ventajas

  • Simple
  • Fácil implementar

Problemas

  • Tiene límites
  • Si falla el servidor, todo cae

Escalado horizontal

Consiste en añadir MÁS servidores.

Ejemplo

1 servidor
↓
10 servidores

Ventajas

  • Mayor disponibilidad
  • Más escalabilidad
  • Más resistencia fallos
AWS utiliza muchísimo el escalado horizontal.

13. Costes y optimización

Problema típico

Tener demasiados servidores permanentemente cuesta dinero.

Sin escalado

10 EC2 activas siempre

Aunque no haya usuarios.

Con Auto Scaling

Poco tráfico → 2 EC2
Mucho tráfico → 10 EC2

Resultado

  • Menor coste
  • Más eficiencia
  • Mejor rendimiento
AWS está diseñado para pagar solo por lo que realmente usamos.
