CLOUD - REPASO FINAL

Cloud Computing

La computación en la nube es un modelo que permite acceder a recursos informáticos mediante internet. Ventajas → Escalabilidad, Elasticidad, Pago por uso y Alta Disponibilidad.

SaaS

Software as a Service proporciona aplicaciones listas para usar. Está orientado a usuarios finales y todo lo gestiona el proveedor. (Gmail, Office 365)

PaaS

Platform as a Service proporciona plataformas listas para desarrollar aplicaciones. Ideal para desarrolladores. (Heroku)

IaaS

Infrastructure as a Service proporciona infraestructura virtual, máximo control. Es el modelo más flexible. (AWS, Azure)

AWS

AWS (Amazon Web Services) (2006) es la plataforma cloud de Amazon. Permite utilizar infraestructura tecnológica a través de internet sin necesidad de comprar servidores físicos.

Región

Ubicación geográfica física donde AWS tiene centros de datos.

Availability Zone (AZ)

Centro de datos aislado dentro de una región.

Puertos

  • 80 → HTTP
  • 443 → HTTPS
  • 22 → SSH
  • 3389 → RDP
  • 25 → SMTP
  • 5432 → PostgreSQL
  • 3306 → MySQL

SSH

SSH permite conectarse remotamente a servidores Linux de forma segura. Puedes hacerlo mediante PuTTY, que usa archivos .ppk

RDP

RDP (Remote Desktop Protocol) permite conectarse gráficamente a servidores Windows.

CIDR

CIDR permite dividir direcciones IP de forma eficiente. La parte después de la barra indica cuántos bits pertenecen a la red.

192.168.1.0/24
--------------------------------
2^8 = 256 IPs totales
256 - 2 = 254 utilizables

Direcciones IP Privadas

  • Rango 10.0.0.0/8 → grandes empresas y CLoud
  • Rango 172.16.0.0/12 → rede medianas
  • Rango 192.68.0.0/16 → Hogar y oficinas

Amazon VPC

Amazon VPC (Virtual Private Cloud) permite crear redes virtuales privadas dentro de AWS → Es como tener tu propia red aislada dentro de la nube.

  • Una VPC pertenece a una región
  • Puede abarcar varias AZ
  • Las subredes pertenecen a una sola AZ

Security Group

Los Security Groups funcionan como firewalls virtuales a nivel de instancia. Son Stateful, permiten tráfico de entrada y salida, solo reglas ALLOW y se aplican a EC2 y recursos concretos

ACLs de red

Las NACL (Network ACL) actúan como firewall a nivel de subred. Son Stateless, controlan entrada y salida, permiten reglas ALLOW y DENY y protegen subredes completas.

Route 53

Amazon Route 53 es el servicio DNS de AWS. Su función principal es traducir nombres de dominio en direcciones IP. Tipos de routing:

  • Simple
  • Weighted
  • Latency
  • Geolocation
  • Failover

CloudFront

CloudFront es la CDN (Content Delivery Network) de AWS. Una CDN distribuye contenido mediante servidores repartidos mundialmente.

Contenedores

Un contenedor es una forma moderna de ejecutar aplicaciones de manera aislada y portable. Incluye TODO lo necesario para ejecutar una aplicación (código, librerías, dependencias, configuración, variables de entorno…)

→ Cada aplicación tiene SU propio entorno aislado. Los contenedores aíslan aplicaciones y dependencias.

🔵 AMAZON EC2

Amazon EC2 (Elastic Compute Cloud) es el servicio de computación de AWS que permite crear servidores virtuales bajo demanda. Es computación.

→ En lugar de comprar un servidor físico real, AWS nos proporciona máquinas virtuales que podemos iniciar, detener, configurar o eliminar en cualquier momento.

Instancias

Una instancia es una máquina virtual que se ejecuta dentro de AWS. Familias comunes:

  • T (como Amazon EC2 T3 t3.micro) son económicas y de uso general con CPU “burstable”, ideales para webs pequeñas y testing.
  • C (como Amazon EC2 C5 c5.large) están optimizadas para alto rendimiento de CPU, ideales para procesamiento intensivo y cálculo.
  • R (como Amazon EC2 R5 r5.large) están optimizadas para gran cantidad de RAM, ideales para bases de datos y caché.
  • P (como Amazon EC2 P3 p3.2xlarge) incluyen GPUs potentes y están pensadas para IA, machine learning y renderizado gráfico.

AMI

Una AMI (AmazonMachine Image) es una plantilla utilizada para crear instancias EC2 rápidamente. Incluye sistema operativo, software y configuración inicial.

Elastic IP

Las IP públicas normales cambian al detener e iniciar instancias. Para evitar esto AWS ofrece Elastic IP. Esto puede ahorrar muchos costes no deseados.

🔵 AMAZON EBS

Amazon EBS (Elastic Block Store) es el sistema de almacenamiento persistente de AWS diseñado principalmente para instancias EC2. Funciona como un disco duro virtual conectado a un servidor cloud. Características:

  • Persistencia
  • Almacenamiento en bloques
  • Escalabilidad
  • Alta disponibilidad
  • Snapshots

→ Cuando una instancia necesita guardar datos importantes, normalmente utiliza EBS.

→ EBS es comparable a un SSD o HDD conectado físicamente a un servidor, pero virtualizado en AWS.

→ Muchas bases de datos empresariales utilizan EBS por su rendimiento y persistencia.

→ AWS permite cifrar volúmenes EBS sin coste adicional

Snapshot

Un snapshot es una copia de seguridad de un volumen EBS. AWS almacena snapshots en S3 internamente. → Las snapshots son incrementales, por lo que optimizan espacio y costes.

Tipos de volúmenes EBS

  • SSD General Purpose → uso general
  • SSD Provisioned IOPS → Máximo rendimiento
  • HDD Throughput Optimized → Acceso secuencial
  • Cold HDD → Bajo coste

🔵 AMAZON S3

Amazon S3 (Simple Storage Service) es el sistema de almacenamiento de objetos de AWS. Está diseñado para guardar archivos de cualquier tipo de manera extremadamente escalable.

→ Los objetos S3 pueden accederse mediante URL en formato path style, virtual-hosted (la más usada actualmente) y URL de objetos.

→ S3 replica automáticamente objetos en múltiples Availability Zones. Esto permite mantener datos disponibles incluso si falla un centro de datos completo.

→ Durabilidad = 99.999999999%

→ Amazon S3 usa un modelo de pago por uso

Buckets y objetos

En S3 los archivos se almacenan como objetos dentro de contenedores llamados buckets.

→ Por defecto, los buckets son privados. Para hacer públicos objetos necesitamos modificar permisos y políticas. Estas están en formato JSON.

  • Allow → permite acceso
  • GetObject → leer objetos
  • Principal "*" → cualquier usuario

Clases de almacenamiento S3

  • S3 Standard: almacenamiento de acceso frecuente con alta disponibilidad y baja latencia, ideal para aplicaciones y contenido activo.
  • S3 Standard-Infrequent Access (Standard IA): almacenamiento más barato para datos poco accedidos pero que requieren acceso rápido cuando se necesiten.
  • S3 Intelligent-Tiering: mueve automáticamente los objetos entre niveles de acceso frecuente e infrecuente para optimizar costes.
  • Glacier: almacenamiento de archivado de bajo coste para datos que no necesitan acceso inmediato.
  • Glacier Deep Archive: la opción más barata de archivado para retención a muy largo plazo con tiempos de recuperación lentos.

🔵 AMAZON RDS

Amazon RDS (Relational Database Service) es el servicio administrado de bases de datos relacionales de AWS. Soporta PostgreSQL, MySQL, MariaDB, Oracle, SQL Server y Amazon Aurora.

→ Aurora es la base de datos propia de AWS compatible con MySQL y PostgreSQL.

→ Al crear una base de datos RDS debemos elegir varios elementos fundamentales: clase de instancia, almacenamiento y motor.

→ Por seguridad, las bases de datos RDS suelen colocarse en subredes privadas.

→ RDS cobra principalmente mientras la base de datos está activa.

Motores de bases de datos

  • PostgreSQL → Open source avanzado
  • MySql → Aplicaciones web
  • Aurora → Máximo rendimiento AWS

→ También podemos instalar manualmente PostgreSQL dentro de una instancia EC2 Ubuntu. systemctl enable --now postgresql

AWS Database Migration Service (DMS)

Permite migrar bases de datos hacia AWS de forma rápida y segura, manteniendo la base de datos de origen operativa durante la migración.

🔵 AWS DYNAMODB

Amazon DynamoDB es una base de datos NoSQL completamente administrada por AWS. Está diseñada para aplicaciones que necesitan:

  • Escalabilidad extrema
  • Baja latencia
  • Alta disponibilidad
  • Rendimiento constante

→ DynamoDB utiliza principalmente modelo clave-valor y documentos.

→ Aunque DynamoDB sea NoSQL, sigue usando el concepto de tablas: tabla como contenedor principal, ítem como registro individual y atributo como dato concreto.

→ DynamoDB + Lambda: DynamoDB se integra perfectamente con arquitecturas serverless. Lambda suele usar boto3 para conectarse a DynamoDB.

Claves DynamoDB

  • Partition Key → Es la clave principal usada para identificar y distribuir datos.
  • Sort Key → Permite ordenar múltiples registros relacionados.
{
 "usuario":"Ana", #Partition Key
 "fecha":"2026-05-15" #Sort Key
}

DynamoDB Streams

DynamoDB Streams captura una secuencia temporal de las modificaciones de los elementos en una tabla, permitiendo disparar eventos (ej. invocar una función Lambda al instante).

PartiQL

PartiQL es un lenguaje de consultas compatible con SQL que facilita a los desarrolladores tradicionales hacer operaciones en tablas de DynamoDB.

Multi AZ

Los despliegues Multi-AZ (Múltiples Zonas de Disponibilidad) mantienen una réplica síncrona en espera en otro centro de datos para asegurar el servicio en caso de fallo de infraestructura.

Query y Scan

Query busca datos usando claves y es muy rápido; Scan recorre toda la tabla y es más lento.

APIS y JSON

DynamoDB trabaja muchísimo con APIs y formato JSON. Una API es un intermediario que permite comunicación entre programas. Usa mucho JSON.

🔵 AWS LAMBDA

AWS Lambda es el servicio serverless de AWS que permite ejecutar código sin administrar servidores. La función solo existe mientras se ejecuta.

En lugar de crear una máquina EC2 completa, simplemente subimos una función y AWS se encarga automáticamente de:

  • Infraestructura
  • Escalado
  • Disponibilidad
  • Ejecución
  • Monitorización básica

→ Lambda revolucionó muchas arquitecturas modernas porque elimina gran parte de la administración de servidores.

→ Serverless NO significa que no existan servidores. Significa que los servidores son completamente administrados por AWS y nosotros no tenemos que preocuparnos por ellos.

→ Lambda trabaja completamente mediante eventos. Una función Lambda no permanece activa permanentemente como EC2 (límite 15 minutos). La función principal suele llamarse lambda_handler.

→ Lambda soporta muchos lenguajes, principalmente Python, pero también Node.js, Java, C#, Java, Go y Ruby.

→ Lambda necesita permisos para interactuar con otros servicios AWS. Los permisos se obtienen mediante roles IAM.

→ Uno de los usos más comunes es encender y apagar servidores automáticamente, automatizando EC2.

→ Lambda no sustituye completamente a EC2; ambos servicios se complementan.

CloudWatch

CloudWatch monitoriza funciones Lambda automáticamente (logs, errores, tiempo de ejecución, invocaciones, uso de memoria…) → CloudWatch es fundamental para detectar errores en arquitecturas serverless.

API Gateway

API Gateway permite exponer funciones Lambda mediante HTTP. → API Gateway suele ser la puerta de entrada HTTP en arquitecturas serverless.

🔵 AWS EBS (Elastic Beanstalk)

AWS Elastic Beanstalk es un servicio administrado que permite desplegar aplicaciones web automáticamente sin configurar manualmente toda la infraestructura. El objetivo principal es simplificar el despliegue de aplicaciones.

  • Crea servidores EC2
  • Configura balanceadores
  • Gestiona Auto Scaling
  • Configura monitoreo
  • Despliega aplicaciones

→ Elastic Beanstalk permite centrarse en programar sin perder completamente el control de AWS.

→ Cuando desplegamos una aplicación, Elastic Beanstalk crea automáticamente múltiples servicios AWS.

→ Elastic Beanstalk NO reemplaza EC2. Simplemente automatiza su administración. Si miramos la consola EC2 veremos servidores creados automáticamente por Beanstalk

→ Soporta servidores NGINX, Apache, IIS y Puma.

→ Elastic Beanstalk puede aumentar o reducir servidores automáticamente. Esto se conoce como Auto Scaling. Auto Scaling es fundamental en aplicaciones con tráfico variable.

→ Elastic Beanstalk utiliza CloudWatch para monitorización.

→ Muchos alumnos creen que Beanstalk reemplaza costes EC2; realmente sigue usando recursos AWS normales.

→ Beanstalk es muy útil para aprender cloud antes de pasar a arquitecturas más avanzadas como Kubernetes o ECS.

Balanceadores de carga

El balanceador distribuye tráfico entre múltiples servidores para evitar saturación, ofrecer mayor disponibilidad y distribuir el tráfico.

Alta disponibilidad

La alta disponibilidad (High Availability o HA) es un concepto fundamental en cloud computing. El objetivo es que una aplicación permanezca funcionando incluso cuando algo falla.

→ Alta disponibilidad NO significa “nunca falla”, sino minimizar caídas.

→ En arquitecturas modernas es importante no depender de un único servidor, ya que esto puede suponer un punto único de fallo e implicar la caída de todo el sistema.

🔵 AWS ELB

Elastic Load Balancing es el servicio AWS encargado del balanceo de carga. El balanceo de carga consiste en repartir tráfico entre varios servidores.

Funcionamiento básico

Usuario entra web
↓
ELB recibe petición
↓
ELB decide servidor
↓
Servidor responde

Health Checks

ELB comprueba constantemente si los servidores siguen vivos. ELB mejora disponibilidad porque evita enviar tráfico a servidores rotos.

Tipos de Load Balancers

  • ALB (Application Load Balancer) → el más usado actualmente. Trabaja en la capa 7 (HTTP/HTTPS) distribuyendo el tráfico (Recomendado para aplicaciones web modernas)
  • NLB (Network Load Balancer) → distribuye tráfico TCP/UDP a muy alta velocidad y baja latencia a nivel de red (capa 4).
  • CLB (Classic Load Balancer) → es el modelo antiguo, trabaja en capas 4 y 7.

Auto Scaling

Auto Scaling permite crear o eliminar servidores automáticamente según demanda.

  • Scale Out (cuándo): el escalado ascendente consiste en añadir más instancias o recursos cuando aumenta la demanda para repartir la carga de trabajo.
    → Una aplicación web pasa de 2 a 6 instancias EC2 durante el Black Friday para soportar más usuarios.
  • Scale In (cuándo): el escalado descendente consiste en reducir la cantidad de instancias o recursos cuando baja la demanda, optimizando costos.
    → Por la noche, una aplicación reduce automáticamente de 6 a 2 instancias EC2 porque hay menos tráfico.
  • Vertical Scaling (cómo): implica aumentar la capacidad de una sola instancia, por ejemplo agregando más CPU, RAM o almacenamiento.
    → Cambiar una instancia EC2 de tipo t3.medium a m5.large para mejorar el rendimiento de una base de datos.
  • Horizontal Scaling (cómo): consiste en agregar más servidores o instancias iguales para distribuir la carga entre varios nodos.
    → Un balanceador de carga distribuye usuarios entre 10 instancias EC2 idénticas en lugar de usar un solo servidor muy potente.

🔵 AMAZON ECS

Amazon ECS (Elastic Container Service) es el servicio AWS para almacenar y ejecutar contenedores Docker.

  • Gestiona contenedores
  • Escala automáticamente
  • Distribuye carga
  • Coordina despliegues

Docker

Docker es la plataforma más famosa para trabajar con contenedores. Algunos conceptos:

  • Imagen Docker → (receta)es como una plantilla que contiene aplicación, dependencias y configuración.
  • Contenedor → (comida preparada) es la instancia en ejecución de una imagen.
  • Dockerfile → es un archivo con instrucciones para crear imágenes.
  • Kubernetes → Es una plataforma para coordinar contenedores automáticamente. Docker ejecuta contenedores. Kubernetes coordina MUCHOS contenedores.

Monolitos vs Microservicios

Una aplicación monolítica tiene todos sus componentes (frontend, backend, base de datos, lógica de negocio) dentro de un único proyecto o servicio.

Los microservicios dividen la aplicación en varios servicios pequeños e independientes, cada uno con una función específica.
