4.16 Backups

Un backup es una copia de seguridad creada para restaurar información tras pérdidas, fallos o ataques.

Objetivos principales

  • Recuperar datos borrados
  • Proteger frente a ransomware
  • Recuperación ante fallos físicos
  • Garantizar continuidad operativa
  • Cumplir normativas

Qué puede destruir datos

Problema Consecuencia
Ransomware Cifrado masivo
Error humano Borrados accidentales
Fallos hardware Pérdida física
Desastres Caída total
⚠ RAID NO sustituye backups.
💡 Un backup sin pruebas de restauración no es fiable.

4.17 Backup Completo

El backup completo copia absolutamente todos los datos seleccionados.

Ventajas

  • Restauración sencilla
  • Alta fiabilidad
  • Menor complejidad

Desventajas

  • Consume mucho espacio
  • Mayor tiempo de ejecución
  • Mayor tráfico de red
Aspecto Backup Completo
Velocidad backup Lenta
Velocidad restauración Muy rápida
Espacio requerido Muy alto

Uso típico

  • Copias semanales
  • Servidores críticos
  • Puntos de referencia
💡 Todo sistema incremental o diferencial parte de un full backup.

4.18 Backup Incremental

El backup incremental solo guarda cambios desde el último backup realizado.

Ventajas

  • Muy rápido
  • Ahorro de espacio
  • Menor tráfico

Problemas

  • Restauración más compleja
  • Dependencia de múltiples backups
  • Mayor riesgo si un incremental falla

Proceso de restauración

  1. Restaurar full backup
  2. Aplicar TODOS los incrementales
⚠ Si falta un incremental, la cadena puede romperse.
💡 Muy usado en backups diarios empresariales.

4.19 Backup Diferencial

El backup diferencial guarda todos los cambios desde el último backup completo.

Diferencia frente a incremental

Tipo Comportamiento
Incremental Cambios desde el último backup
Diferencial Cambios desde el último full

Ventajas

  • Restauración más simple
  • Menor dependencia
  • Buen equilibrio

Problemas

  • Crecen rápidamente
  • Consumen más espacio con los días
💡 Restaurar requiere solo el full y el último diferencial.

4.20 Estrategia GFS (Grandfather-Father-Son)

GFS es una estrategia híbrida muy usada en empresas.

Estructura

Nivel Frecuencia
Son Diario
Father Semanal
Grandfather Mensual

Ventajas

  • Gran equilibrio
  • Histórico amplio
  • Buena recuperación
  • Optimización de espacio

Uso profesional

  • Empresas medianas
  • Servidores críticos
  • Entornos virtualizados
💡 GFS es muy preguntado en exámenes.
⚠ GFS necesita buena planificación de retención.

4.23 DRP (Disaster Recovery Plan)

Un DRP define procedimientos para recuperar sistemas tras un desastre.

Objetivos

  • Reducir downtime
  • Recuperar servicios
  • Minimizar pérdidas
  • Garantizar continuidad

Desastres típicos

Evento Impacto
Incendio Pérdida física
Ransomware Cifrado masivo
Apagón Caída total
Error humano Borrados críticos
💡 Un DRP debe estar documentado y probado.
⚠ Un DRP no probado puede fallar en producción.

4.24 Objetivos Clave del DRP: RPO y RTO

RPO

Define cuántos datos se pueden perder.

Ejemplo: RPO = 4 horas

La empresa acepta perder hasta 4 horas de información.

RTO

Define cuánto tiempo puede estar caído un servicio.

Ejemplo: RTO = 2 horas

El sistema debe volver antes de 2 horas.

Concepto Pregunta
RPO ¿Cuántos datos puedo perder?
RTO ¿Cuánto tiempo puedo estar caído?
⚠ Cuanto menores sean RPO y RTO, mayor coste.

4.25 Alta Disponibilidad (HA)

La Alta Disponibilidad busca minimizar interrupciones mediante redundancia.

Elementos HA

  • Clústeres
  • Failover automático
  • Balanceadores
  • Redes redundantes
  • Fuentes duplicadas

Ventajas

  • Menor downtime
  • Continuidad operativa
  • Failover rápido

Conceptos importantes

Concepto Descripción
HA Minimiza interrupciones
FT Tolerancia total a fallos
⚠ HA NO es lo mismo que Fault Tolerance.
💡 HA suele reducir RTO a segundos o minutos.

4.27 Interconexión: DRP, HA y Backup

Estos tres pilares forman la base de la continuidad empresarial moderna.

Tecnología Objetivo
Backup Recuperar datos
DRP Recuperar operaciones
HA Evitar interrupciones

Relación entre ellos

  • HA reduce interrupciones
  • Backup protege información
  • DRP coordina recuperación

Escenario real

  • HA mantiene servicios activos
  • Backup restaura archivos dañados
  • DRP organiza recuperación total
💡 Las empresas modernas combinan las tres estrategias.
⚠ Tener solo backups NO garantiza continuidad empresarial.
